# Experiment Console Baseline

This document records the read-only baseline used by the independent experiment console.

## Existing Inputs

| Capability | Existing source | Read-only usage |
| --- | --- | --- |
| High-level training | `legged_gym_go2/legged_gym/scripts/train_reach_avoid.py` | Process command target; no source edits |
| Interactive playback | `legged_gym_go2/legged_gym/scripts/play_reach_avoid.py` | Reference only; no process launch in the baseline |
| Trajectory collection | `legged_gym_go2/legged_gym/scripts/test_reach_avoid.py` | Reads its JSON output format |
| Policy export helper | `legged_gym_go2/legged_gym/utils/helpers.py` | Reference for a future isolated adapter |
| Training metrics | `logs/**/training.log` | Parse lines beginning with `iter` |
| High-level checkpoints | `logs/**/model_*.pt`, `model_final.pt` | Read metadata and state-dict shape only |
| Low-level checkpoint | `logs/rough_go2/**/model_*.pt` or exported policy files | Display/reference; not overwritten |
| Videos | `logs/**/*.mp4`, `webui/assets/*.mp4` | Serve as controlled static media |
| Trajectories | JSON generated by `test_reach_avoid.py` | Draw XY paths in a browser canvas |

## Observed Contracts

- High-level checkpoints written by `train_reach_avoid.py` contain `actor_critic`, `optimizer`, `iteration`, `success_rate`, `execution_cost`, and `low_level_model_path`.
- The training log contains lines with `iteration`, `success`, `cost`, `policy_loss`, `value_loss`, `Vmean`, `Rmean`, `Vrmse`, `VexpVar`, and `adv_std`.
- The trajectory collector writes a JSON object containing `checkpoint_path`, `num_trajs`, `max_steps`, `low_level_model`, and `trajectories`; each trajectory is an ordered list of XY pairs.
- The existing high-level observation/action dimensions are currently 40 and 3, but the console treats model dimensions as metadata rather than hard-coded runtime assumptions.

## Non-invasive Boundary

- New implementation files belong under `training_console/`.
- Existing `legged_gym_go2/`, `rsl_rl/`, `unitree_rl_gym/`, `isaacgym/`, `logs/`, `output/`, and `webui/` files are read-only inputs.
- Exported files must be written under `training_console/exports/`.
- No Isaac Gym, CUDA, training, evaluation, or robot deployment is required for the console design and static validation.

## Known Unknowns

- The local machine does not provide the Isaac Gym/CUDA experiment runtime.
- Existing trajectory JSON files are not present in a stable canonical directory, so the adapter must accept an explicitly configured read-only root and return an empty state when none is found.
- The existing play script contains machine-specific absolute paths; the console must not copy those paths into defaults.
